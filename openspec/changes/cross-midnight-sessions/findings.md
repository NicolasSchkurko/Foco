# Findings — `cross-midnight-sessions` (semantic pass, 2026-10-19)

Recorded by `/spec-verify`. Nothing here was fixed in this pass (it never edits specs or code).

- [ ] The requirement over-promises the lookback: it says the query SHALL look back *"far enough to find the event that opened the session"*, but the code bounds the lookback at the **start of the previous day**, so an app in the foreground for more than 24 hours still has no opening event in the window and its stop is still discarded — evidence: `openspec/changes/cross-midnight-sessions/specs/usage-tracking/spec.md:6` ("look back far enough") vs `app/src/main/java/com/foco/app/data/UsageRepository.kt:67` (`date.minusDays(1)`) and the walkthrough's *Limits and failure modes* — severity **medium** — action: decide between (a) a small follow-up change that MODIFIES the requirement to state the bound ("from the start of the previous day") so the living contract stops over-promising, or (b) accepting the bound as documented. Not filed as an `open_decision` on this change on purpose: it is a follow-up to the *living* wording, and a pending decision here would block this change's own closure for something the code already does as declared.
- [ ] No test pins the changed wiring: the requirement's `[@test]` is the pure `SessionBuilderTest`, which proves the clamp arithmetic, but nothing asserts that the query asks from the previous day's start or that the unlock marks are filtered to the day — evidence: `openspec/changes/cross-midnight-sessions/specs/usage-tracking/spec.md:7` vs `app/src/main/java/com/foco/app/data/UsageRepository.kt:67,81` (the platform adapter has no JVM test by design, and the instrumented suite exercises the path without asserting the window) and `tasks.md` 2.2 still open — severity **medium** — action: proposal — extract the window computation into a pure function (`dayQueryWindow(date, now)` → day start, lookback start, effective end) and pin it with a JVM test; a small follow-up change. Not a waiver: the arithmetic *is* covered, and the requirement does not claim the wiring is tested.
- [ ] Readability: the day pipeline nests three calls inside `filterSessions(...)`, so the reader has to work inside-out — evidence: `app/src/main/java/com/foco/app/data/UsageRepository.kt:96-107` — severity **low** — action: hoist `clampSessionsToDay(buildSessions(...), …)` into a named local the next time this file is touched; not worth a change of its own.
